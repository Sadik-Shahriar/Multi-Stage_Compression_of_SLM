\begin{abstract}
The energy cost of language-model inference is a growing Green Computing concern. Small Language Models (SLMs) reduce model computation, but their Key-Value (KV) caches still grow with context length and create conflicting energy, latency, memory, and quality requirements. Weight quantization (AWQ), token eviction (PyramidKV), and KV-cache quantization (TurboQuant) address different parts of this problem, yet their practical effects may not remain additive when composed. This proposal presents a multi-objective empirical ablation of these techniques on Llama 3.2-3B-Instruct using an NVIDIA T4. Five core configurations are evaluated at 1024, 2048, and 4096 tokens, followed by focused TurboQuant bit-width and PyramidKV retention-budget studies. GPU energy is sampled at 10~Hz, inference is separated into prefill and fixed-work decode phases, and retrieval quality is measured independently with randomized Needle-in-a-Haystack prompts. The study seeks Pareto-optimal configurations rather than a single universal winner and distinguishes nominal low-bit compression from realized runtime storage in an unfused reference implementation.
\end{abstract}

\begin{IEEEkeywords}
Green AI, energy-efficient inference, KV cache compression, weight quantization, AWQ, TurboQuant, PyramidKV, small language models, edge deployment

\section{Introduction}
% ============================================================

Training and serving large neural models require substantial computational resources \cite{strubell_energy_2019,patterson_carbon_nodate}. As model use scales, inference efficiency becomes a recurring systems concern rather than a one-time training cost.

A central inference bottleneck is the Key-Value (KV) cache inside decoder-only transformers. During generation, the model stores key and value tensors for previous tokens to avoid recomputation. This state grows linearly with sequence length and increases memory traffic during every decode step \cite{liu_kivi_2023,zhang_rdkv_2026}.

Small Language Models (SLMs), those with fewer than 7 billion parameters, are a better option for saving energy. They need fewer computations per token and can run on cheaper hardware without needing cloud servers \cite{husom_sustainable_2025}. But SLMs still have the KV cache problem, especially when users ask them to handle long inputs.

The research community has developed three main techniques to address this problem: weight quantization, token eviction, and KV-cache quantization. These techniques are usually studied separately. To the best of our literature search, their three-way composition has not been evaluated on a sub-4B SLM while tracking real GPU power draw.

This study addresses that gap through a reproducible case study of \mbox{Llama 3.2-3B-Instruct} on a single NVIDIA T4. Llama 3.2-3B is a sub-4B SLM with GQA, official AWQ support, and a tractable cache path that makes all three compression techniques feasible to implement and verify.

The problem is explicitly multi-objective. A configuration that minimizes energy may not minimize latency or memory, and the most compressed configuration may not preserve retrieval quality. The study therefore evaluates Pareto dominance across energy, latency, memory, throughput, and quality rather than assuming that maximum compression is automatically best.

\section{Background}
% ============================================================

To understand this study, it helps to know about transformer KV caches, the three compression strategies, and the selected Llama model.

\textbf{KV Cache Growth}: Transformers store key and value tensors for previous tokens to avoid recalculating them. Cache storage grows as $O(n \times L \times h_{kv} \times d)$, where $n$ is context length, $L$ is the number of layers, $h_{kv}$ is the number of KV heads, and $d$ is head dimension. Its repeated movement between GPU memory levels can make long-context decode memory-bound \cite{li_snapkv_nodate,liu_kivi_2023}.

\textbf{Weight Quantization}: AWQ \cite{lin_awq_2025} protects activation-salient weights while quantizing most model weights to low precision. Its published system combines the algorithm with optimized kernels; therefore, reported speedups are hardware- and implementation-dependent and are not assumed in advance for the T4.

\textbf{Token Eviction}: This approach removes tokens from the KV cache that are not getting much attention. H2O \cite{zhang_h2o_nodate} showed that just 20\% of tokens receive most of the attention. SnapKV \cite{li_snapkv_nodate} (NeurIPS 2024) improved on this by using the last 32 tokens as a ``window'' to predict which older tokens will matter, reporting a 3.6$\times$ generation speedup and 8.2$\times$ memory reduction at 16K tokens. PyramidKV \cite{cai_pyramidkv_2025} (COLM 2025) goes further: it noticed that early layers in a transformer spread attention broadly, while later layers focus on just a few tokens. By giving more cache space to early layers and less to later ones, it achieves 5--15\% better retrieval accuracy than SnapKV at the same memory budget.

\textbf{KV Cache Quantization}: TurboQuant \cite{zandieh_turboquant_2025} applies a data-oblivious random rotation followed by an optimized scalar codebook. The paper reports quality-neutral KV-cache results near 3.5 bits per channel, while related evidence favors preserving dimensions through quantization over rank reduction, particularly for GQA models \cite{salfati_quantization_2026}. This project uses the independent TurboQuant PyPI reference implementation, so algorithmic bit width, physical storage, and kernel efficiency are reported separately.

\textbf{Llama 3.2-3B}: The selected decoder model belongs to the Llama 3 family \cite{grattafiori_llama3_2024}. Its official model card and checkpoint configuration specify 28 transformer layers, 24 query heads, 8 KV heads, a head dimension of 128, and an original 8192-token rotary-position window \cite{meta_llama32_2024}. The experiment uses an FP16 checkpoint and a community AWQ checkpoint configured for 4-bit weights with group size 128 \cite{casperhansen_llama32_awq}. The tested contexts are limited to 4096 because the 8192 condition exceeded the available free-tier T4 memory during pilot development.

\section{Problem Statement}
% ============================================================

Existing work establishes the value of weight quantization, token eviction, and KV-cache quantization, while RDKV and ThinKV show that eviction and quantization should be considered jointly \cite{zhang_rdkv_2026,ramachandran_thinkv_2026}. However, there is limited empirical evidence on how all three compression axes interact on a sub-4B SLM when real GPU energy is measured. Published algorithmic compression ratios also do not guarantee lower wall-clock energy or runtime memory when kernels are unfused or higher-precision working tensors remain reachable.

The research problem is therefore the absence of an implementation-aware, multi-objective comparison that separates the contribution of each technique and measures whether their benefits remain additive across context lengths. The study also addresses two practical uncertainties identified by the literature: how TurboQuant precision changes distortion and runtime cost, and how PyramidKV retention budget changes the energy--quality trade-off.

\subsection{Aim}

The aim of this research is to conduct a multi-objective empirical evaluation of AWQ, PyramidKV, and TurboQuant on \mbox{Llama 3.2-3B-Instruct}, determining how they individually and jointly affect energy, latency, memory, throughput, and retrieval quality on an NVIDIA T4.

\subsection{Objectives}

To achieve this aim, the research will:
\begin{enumerate}
  \item \textbf{Implement and validate} C0 (FP16), C1 (AWQ), C2 (AWQ + PyramidKV), C3 (AWQ + TurboQuant), and C4 (all three), with structural gates proving that the requested cache operations execute.
  \item \textbf{Measure energy efficiency} through prefill, decode, and total joules; idle-adjusted energy; and decode joules per token at 1024, 2048, and 4096 tokens.
  \item \textbf{Measure runtime performance} through prefill latency, decode latency, and throughput under an identical 64-token teacher-forced decode workload.
  \item \textbf{Measure memory efficiency} through peak VRAM, post-prefill memory, post-decode memory, actual cache bytes, and logical compression ratio.
  \item \textbf{Evaluate quality} using randomized, distractor-rich NIAH prompts, reporting retrieval correctness separately from exact-format compliance.
  \item \textbf{Analyze compression sensitivity} using TurboQuant bit widths of 2, 3, and 4 and PyramidKV average budgets of 512, 1024, and 1536 at 4096 tokens.
  \item \textbf{Determine interaction effects} by testing whether PyramidKV and TurboQuant produce additive, antagonistic, or context-dependent behavior when composed.
  \item \textbf{Test differences} with paired parametric or non-parametric procedures, confidence intervals, effect sizes, and multiple-comparison correction.
  \item \textbf{Identify Pareto-optimal choices} for energy-, latency-, memory-, and quality-constrained deployment scenarios.
\end{enumerate}

\subsection{Focus}

This study keeps the model and hardware fixed---Llama 3.2-3B on one T4---so that any differences we see come from the software, not from switching GPUs or models. We trade breadth (testing many models) for a controlled, repeatable experiment. Five core configurations cover the main ablation; two smaller studies add depth by varying TurboQuant bit widths and PyramidKV budgets at 4096 tokens only, without creating a full factorial grid.

We measure several things at once: energy, latency, memory, throughput, and retrieval quality. No single weighted score decides what is best. Instead, a configuration wins on Pareto grounds: it is better if it improves one metric without hurting another. Different deployment scenarios will favor different trade-offs.

\section{Contributions}
% ============================================================

This research makes three focused contributions. \textbf{First}, to the best of our knowledge, it provides an early hardware-energy case study of AWQ, pyramidal KV eviction, and TurboQuant numerical KV quantization composed on a sub-4B SLM. \textbf{Second}, it measures interaction rather than assuming independent compression gains, including focused bit-width and retention-budget sensitivity. \textbf{Third}, it distinguishes logical compression, actual cache storage, and peak runtime memory, and releases reproducible notebooks, validation artifacts, and CSV results.

\section{Related Works}
% ============================================================

Researchers have studied various ways to compress language models. This section reviews the most relevant work across weight quantization, token eviction, KV cache quantization, compound methods, and energy measurement.

\textbf{Weight Quantization:} Lin et al.\ \cite{lin_awq_2025} developed AWQ, which protects activation-salient weights and enables low-bit deployment when paired with suitable kernels. Frantar et al.\ \cite{frantar_gptq_2023} proposed GPTQ as a second-order alternative. The broader SLMQuant benchmark \cite{wang_slmquant_2025} shows that compression behavior does not transfer uniformly from large models to SLMs, motivating direct measurement on Llama 3.2-3B.

\textbf{Token Eviction:} Zhang et al.\ \cite{zhang_h2o_nodate} showed that only about 20\% of tokens in the KV cache actually matter, which they called the Heavy Hitter Oracle. Li et al.\ \cite{li_snapkv_nodate} built on this with SnapKV, which uses a short observation window to figure out which tokens can be safely removed, achieving large memory savings at 16K context. Cai et al.\ \cite{cai_pyramidkv_2025} improved further with PyramidKV, which uses a pyramidal budget across layers and beats SnapKV by 5--15\% NIAH accuracy.

\textbf{KV Cache Quantization:} Zandieh et al.\ \cite{zandieh_turboquant_2025} proposed TurboQuant, which uses random rotation and an optimized scalar codebook without calibration data. Liu et al.\ \cite{liu_kivi_2023} offered KIVI as a 2-bit alternative. Salfati \cite{salfati_quantization_2026} showed that preserving dimensions through quantization can outperform rank reduction, with a growing advantage for GQA. These results motivate both TurboQuant and the proposed bit-width sensitivity analysis.

\textbf{Compound Methods:} Zhang et al.\ \cite{zhang_rdkv_2026} jointly allocate eviction and quantization through a rate-distortion formulation and report strong long-context accuracy and throughput. ThinKV \cite{ramachandran_thinkv_2026} likewise uses hybrid quantization and eviction for reasoning models. These methods demonstrate that joint compression is important, but neither supplies the proposed sub-4B T4 energy ablation of AWQ, PyramidKV, and TurboQuant.

\textbf{Energy Measurement:} Argerich et al.\ \cite{argerich_watt_2026} published Watt Counts (2026), a large benchmark covering 5,000+ LLM inference experiments. They established that T4 GPUs draw about 12W idle and up to 82W at peak, and selected 10 Hz (100 ms) polling via pynvml as the best accuracy--overhead trade-off after evaluating rates from 1 Hz to 200 Hz. Table~\ref{tab:comparison} summarizes how this study compares to all existing work.

\section{Research Questions}
% ============================================================

The main research question is: when AWQ, PyramidKV, and TurboQuant are applied individually and together on Llama 3.2-3B, how do their energy, latency, memory, throughput, and retrieval-quality trade-offs change with context length on a T4 GPU?

This breaks down into three specific sub-questions:

\begin{enumerate}
\item \textbf{RQ1:} How do the five core configurations affect prefill and decode energy, latency, throughput, peak and persistent memory, and NIAH retrieval at 1024, 2048, and 4096 tokens?

\item \textbf{RQ2:} How do TurboQuant bit width and PyramidKV average retention budget change numerical distortion and the energy--quality--memory trade-off, and are their benefits additive in C4?

\item \textbf{RQ3:} Which configurations are Pareto-optimal for energy-, latency-, memory-, and quality-constrained deployment scenarios?
\end{enumerate}

Based on the literature and implementation-aware pilot observations, the confirmatory study tests the following directional hypotheses:

\textbf{H1 (AWQ context effect):} The energy advantage of AWQ over FP16 increases with context length.

\textbf{H2 (PyramidKV long-context benefit):} At 4096 tokens, C2 reduces decode energy per token and increases throughput relative to C1 while keeping retrieval accuracy within five percentage points.

\textbf{H3 (TurboQuant reference overhead):} The unfused TurboQuant 0.2.0 path in C3 increases decode latency and energy relative to C1 at the tested contexts because its online quantization and dequantization overhead is not hidden by fused low-bit attention kernels.

\textbf{H4 (Compound interaction):} At 4096 tokens, C4 uses less energy and lower latency than C3 but more energy and lower throughput than C2, demonstrating non-additive interaction.

\textbf{H5 (Context-dependent ranking):} The relative efficiency ranking changes with context length, with eviction-based configurations becoming more beneficial as context grows.

For each directional hypothesis, the corresponding null states that the specified contrast or interaction is absent after multiple-comparison correction.

\section{Planned Methodology}
% ============================================================

\begin{figure}[htbp]
\centering
\includegraphics[width=\linewidth]{methodology diagram.png}
\caption{Methodological framework of the multi-objective empirical ablation study and parameter sensitivity analysis on Llama 3.2-3B-Instruct.}
\label{fig:methodology}
\end{figure}

The experiment runs on a single NVIDIA T4 in Google Colab with a pinned Python environment, as illustrated in Fig.~\ref{fig:methodology}. Five core configurations (C0--C4, see Table~\ref{tab:configs}) are tested at 1024, 2048, and 4096 tokens, each repeated five times in randomized order. Two smaller studies at 4096 tokens vary TurboQuant bit width (2, 3, 4) and PyramidKV budget (512, 1024, 1536).

\textbf{Environment:} The FP16 baseline uses \texttt{unsloth/Llama-3.2-3B-Instruct}; AWQ uses \texttt{casperhansen/llama-3.2-3b-instruct-awq}. GPU power is sampled at 10 Hz via pynvml \cite{argerich_watt_2026} and integrated over measured timestamps. Temperature, clocks, and power limits are recorded alongside energy to flag anomalous runs.

\textbf{Metrics:} Energy uses a fixed 64-token teacher-forced decode so that measured work is identical across configs. Quality uses randomized NIAH prompts at three depths (10\%, 50\%, 90\%) with five seeds; retrieval correctness and format compliance are scored separately. Perplexity is excluded because a pre-compression loss cannot capture the effect of a cache modified after prefill. Memory is reported as peak VRAM and persistent cache bytes.

\textbf{Validations:} Every run checks that the requested bit width, eviction budget, and quantization path are actually executing. Configs that fail a gate are reported as blocked rather than included with incorrect settings.

\textbf{Analysis:} Paired comparisons use t-tests or Wilcoxon as appropriate, with Holm correction for multiple contrasts. The final report uses four primary plots: energy vs.\ context, throughput vs.\ energy, peak vs.\ persistent memory, and Pareto fronts across all objectives. Recommendations target specific deployment constraints rather than a single weighted score.
